How do programs remember data across iterations?
Three approaches — each more powerful than the last.

→ loop   → array   → vector
The Setup

You're tracking dungeon XP

Your party just cleared a 5-floor dungeon. You tracked XP as you went. At the end, you want to know:

  • 1
    What was the total XP for the run?
  • 2
    What was the average per floor?
  • 3
    Which floor was the hardest? (most XP)
  • 4
    Can we graph the run?
⚡ key question

Questions 3 and 4 require going back and looking at individual values. Can a simple loop do that?

DUNGEON RUN LOG
Floor 1 ····· 120 XP
Floor 2 ····· 85 XP
Floor 3 ····· 210 XP
Floor 4 ····· 95 XP
Floor 5 ····· 160 XP
Total ······ 670 XP
Approach 1

Loop with a running total

C++
#include <iostream>
using namespace std;

void partOne() {
    const int FLOORS = 5;
    int total = 0;
    int xp;

    // Loop through each floor
    for (int i = 0; i < FLOORS; i++) {
        cout << "Floor " << (i+1) << " XP: ";
        cin >> xp;
        total += xp;     // accumulate
    }

    double avg = (double)total / FLOORS;
    cout << "Total: "   << total << "\n";
    cout << "Average: " << avg   << "\n";
}
✓ what works

Total and average — done. We process each value as it arrives.

✗ the problem

Once the loop ends, individual values are gone. xp holds only the last input. We can't graph, compare, or re-examine anything.

The Big Idea

Memory has an address

An array is a contiguous block of memory — all cells the same type, laid out in a row, each accessible by index number.

int xp[5]; ← 5 integers, side by side
random access

xp[2] gives you floor 3 instantly. Jump to any element, any time.

size is fixed at compile time

You declare how many slots you need. The compiler reserves exactly that much space.

Approach 2

Store everything in an array

C++
void partTwo() {
    const int FLOORS = 5;
    int xp[FLOORS];    // array — 5 slots
    int total = 0;

    // Collect data
    for (int i = 0; i < FLOORS; i++) {
        cout << "Floor " << (i+1) << " XP: ";
        cin >> xp[i];   // store it!
        total += xp[i];
    }

    cout << "Average: " << (double)total/FLOORS;

    // ★ Now we can look back
    cout << "\n\nXP by floor:\n";
    for (int i = 0; i < FLOORS; i++) {
        cout << "Floor " << (i+1) << ": "
             << xp[i] << "\n";
    }
}
✓ what's new

Every value is preserved. We can loop over the data again to display, compare, or graph it.

Bonus Feature

The ASCII bar chart

Because we stored the data, we can visualize it. The trick: print one █ character per N XP.

C++
void barChart(int xp[], int floors) {
    const int SCALE = 10;  // 1 bar = 10 XP
    for (int i = 0; i < floors; i++) {
        cout << "F" << (i+1) << " | ";
        for (int b = 0; b < xp[i]/SCALE; b++)
            cout << "█";
        cout << " " << xp[i] << "\n";
    }
}

The Catch

Arrays have a fixed size

Arrays are declared at compile time. You must know the size before the program runs.

C++
int xp[5];    // ✓ fine — exactly 5
int xp[100];  // ✓ works — wastes slots if user has fewer
int n;
cin >> n;
int xp[n];    // ⚠ VLA — works in GCC but not standard C++
⚡ real-world scenario

What if the dungeon has a random number of floors? Or the user picks how many sessions to track?

→ the solution

A container that can grow at runtime. In C++, that's std::vector.

Approach 3

std::vector — arrays that grow

C++
#include <vector>
#include <numeric>   // for accumulate
#include <algorithm> // for max_element

void partThree() {
    vector<int> xp;   // starts empty
    int floors;

    cout << "How many floors? ";
    cin >> floors;

    for (int i = 0; i < floors; i++) {
        int val;
        cout << "Floor " << (i+1) << ": ";
        cin >> val;
        xp.push_back(val);  // ← grows automatically
    }

    int total = accumulate(xp.begin(), xp.end(), 0);
    auto best = *max_element(xp.begin(), xp.end());

    cout << "Total: " << total << "\n";
    cout << "Best floor: " << best << " XP\n";
}
✓ dynamic sizing

push_back() adds one element at a time. The vector manages its own memory.

✓ STL algorithms

accumulate and max_element replace manual loops entirely.

note for now

Vectors come later in the course. For this module, arrays are the target. This is a preview of where we're headed.
